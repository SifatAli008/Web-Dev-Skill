Four Core Engineering Pillars

1. Route via Index (Context Conservation)

Agents read skills.index.json and load only the 2 to 5 specialists needed for the immediate task. The entire repository is never dumped into the context window, preventing context saturation and cognitive dilution.

2. Three-Tier Rigor Matrix (Match Discipline to Stakes)

Projects are classified as MVP (internal / prototype speed), PROD (public users, auth, payments, customer data), or SCALE (>100k MAU, spiky load, SLAs). PROD/SCALE invariants are never bypassed without explicit user sign-off in DECISIONS.md.

3. Hard Vetos & Evidence-First Gates (No Evidence, No Ship)

Application Security holds unilateral veto power over SQL injection, secret leaks, and insecure crypto. Privacy Officer holds unilateral veto over non-compliant tracking. QA mandates terminal test exit code 0 before code merge.

4. Zero AI Garbage Standard (No Vibe Code)

Strict automated hygiene linters fail any PR containing placeholder comments (/* stub */), synthetic wrappers, fake statistics, or hollow mockup cards. Only dense, production-grade interactive craft is permitted.

3-Tier Rigor Matrix Comparison

Every project is classified into one of three rigor tiers based on concrete operational signals. Always build to the highest tier triggered:

MVP Tier Prototype Speed

For internal tools, proofs of concept, and early customer discovery where speed of validation takes priority.

  • Signals: Internal only, zero payments, mock auth, disposable data.
  • Testing: Happy-path unit tests; smoke test passes.
  • Gates: Basic linting; security veto relaxed for prototypes.
PROD Tier Production Rigor

For any public application, real customer accounts, payments, or sensitive data capture.

  • Signals: Public internet, user accounts, email capture, Stripe checkout.
  • Testing: Comprehensive unit, integration, and Playwright E2E tests.
  • Gates: Hard Security Veto, Privacy Veto, Zero-Downtime DB migrations.
SCALE Tier High-Volume Enterprise

For high-volume platforms, multi-tenant boundaries, spiky traffic, and strict SLA requirements.

  • Signals: >100k MAU, spiky throughput, high financial volume, regulated PII.
  • Testing: Load & stress testing, chaos engineering, edge cache hit ratio audits.
  • Gates: Circuit breakers, automated rollback, telemetry APM, multi-region SLAs.

The 5 Binding Quality Gates

Five specialists hold unilateral authority to block shipments or deployments until verifiable terminal evidence passes:

1. Application Security Lead (06-security) HARD VETO

Blocks any shipment containing hardcoded secrets, SQL injection, insecure crypto, unescaped user inputs, or vulnerable dependencies.

2. Privacy & Compliance Officer (07-privacy-compliance) HARD VETO

Blocks any code with unconsented third-party tracking, missing GDPR/CCPA consent banners, or unencrypted PII at rest.

3. SQAT & SDET Lead (08-testing-qa) NO EVIDENCE, NO SHIP

Mandates terminal test suite execution with exit code 0 and automated E2E verification before any merge or release.

4. DevOps Lead (09-devops-infra) NO ROLLBACK, NO SHIP

Requires verified automated rollback mechanisms, health probes (/api/health/liveness & readiness), and zero-downtime database migrations.

5. Launch Operations Manager (13-launch-operations) LAUNCH GATE

Synthesizes sign-offs from all 4 upstream gates into templates/schemas/launch-report.schema.json with explicit launch_decision: "GO".

Agent Execution Modes

Universal WebDev Skills runs natively across both single-agent and multi-agent IDE environments:

  • Multi-Agent Mode: Spawn parallel subagents per specialist role. Context is exchanged strictly via schema-validated markdown handoffs in templates/schemas/.
  • Single-Agent Mode: The agent wears one specialist hat at a time (declared via [Wearing: Specialist Role]), completes its operational checklist, generates the handoff artifact, and transitions cleanly.
  • Conflict Order: In any architectural dispute, the priority order is strictly: Security & Privacy > Architecture > Performance > Speed.
